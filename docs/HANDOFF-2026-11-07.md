## First thing to do after the reboot

1. Check RAM: `free -g` should show about 64 GB. Raise the ComfyUI limits (they are 20G/22G for a 30 GB box):
   ```sh
   mkdir -p ~/.config/systemd/user/comfyui.service.d
   printf '[Service]\nMemoryHigh=44G\nMemoryMax=50G\nMemorySwapMax=2G\n' > ~/.config/systemd/user/comfyui.service.d/memory.conf
   systemctl --user daemon-reload
   ```
   (Peak seen: 18 GB ComfyUI RSS, 27 GB system. With 64 GB a paint run no longer starves the rest, so Blender, the
   viewer and Godot can run next to it. The per-monster ComfyUI restart is no longer needed for memory: `--no-restart`.)
2. Start ComfyUI (only through the unit, never nohup): `systemctl --user start comfyui`.
3. Paint what is ready:
   ```sh
   python3 -I tools/batch.py run --ids goblin-warrior --include-pilots --n 4 --max-fast-failures 8   # tier-0 pilot, quiver re-roll
   python3 -I tools/batch.py run --tier 1-3 --include-pilots --n 4 --max-fast-failures 8            # the rest (about 1 h)
   python3 -I tools/batch.py report
   ```
   `~/.cache/monster-forge-scratch/queue.sh` is the overnight loop (create/remove `QUEUE_DONE` to stop/start it).
4. Optional: the viewer, `python3 -I tools/viewer.py` (add `--host 0.0.0.0` for the LAN: non-loopback
   clients are read-only; http://192.168.1.12:8787/).
